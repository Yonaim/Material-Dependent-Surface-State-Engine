# Markdown / Vault Writing Standard

## 기본 규칙

- **한 문서 = 하나의 책임.** 결론·핵심 사용법·관련 진입점을 상단에 배치한다.
- 동일한 정의의 정본을 하나만 둔다. 다른 문서는 **링크**한다.
- 일반 Markdown과 Obsidian 모두에서 접근할 수 있도록 **상대 경로 Markdown 링크**를 우선 사용한다.
- 파일 이동·삭제 시 Document Map, 관련 문서 링크, 소스 경로를 함께 확인한다.
- 새 하위 문서가 많아졌을 때만 지역 `00_Index.md`를 추가하며 인덱스에는 상세 설명을 복제하지 않는다.
- 미정, 설계안, 정적 코드 확인, 실제 테스트 통과를 혼동하지 않는다. 확인 근거와 날짜가 필요하면 기재한다.
- 실제 수행하지 않은 실험·빌드·테스트 결과나 임의 측정 수치는 기록하지 않는다.
- 이미지/로그/원자료는 출처·생성 방법·실제 저장소 경로를 남긴다. 대규모 바이너리나 성능 원자료를 볼트에 무작정 복사하지 않는다.

## 문서 책임

| 주제 | 정본 위치 |
|---|---|
| 개발 행동 규칙 | `00_Engineering-Standards` |
| 목표·용어·요구·제약 | `01_Project-Context` |
| 현재 실행 단계·계약·핵심 모듈 | `02_Architecture` |
| 현재 진행 중 작업·작업 로그 | `04_Development` |
| 실제 검증 및 재현 정보 | `05_Experiments` |
| 설계 의사결정의 맥락·대안·근거 | `03_Decisions` |

## 문서 상태

필요하면 `상태: 미작성 / 설계안 / 현재 구현 기준 확인 / 검증 완료`를 명시한다. 확인되지 않은 초기 템플릿 필드는 `{{PLACEHOLDER}}`로 남긴다.

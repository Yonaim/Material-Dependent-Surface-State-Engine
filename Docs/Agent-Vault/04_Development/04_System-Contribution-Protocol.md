# MDSSP 시스템 기여 가설 — 사전 실험 명세

> **한 줄 요약:** 공통 State·Reaction·State-Driven Geometry Coupling의 기전, 재사용성, 구조적 이점과 신규성을 분리해 반증한다. 이 문서는 계획이며 결과가 아니다.

- 문서 버전: 0.1 · 2026-10-26
- 코드 확인 기준: `880af1ebcffe601f0bac27413cad94055ce92812`
- 상태: **1차 기전 실험 분석 완료 · 후속 Baseline 명세 v1 작성** (2026-10-27). 앞 절의 미구현/미실행 표기는 원래 계획 시점이며 실행 이력은 §12와 PERF-041을 따른다.
- 승인된 작업 범위: 사용자의 “이제 실험하고 결과 분석해줘” 지시에 따라 필요한 실험 제어·계측 및 실험 실행·분석을 진행한다. 이전 분석 전용 제한은 이 범위에서 해제되었다.
- 기록 유형: 현행 구현을 읽은 사전 연구 설계. 구현 성능 비교 결과나 확정된 Contribution으로 해석하지 않는다.
- 후속 성능 측정은 [[05_Experiments/02_Performance-Measurements|성능 문서]]와 [[02_Docs_Template-Experiment|실험 양식]]에 기록한다. 실행마다 별도 설명 문서를 만들지 않는다.

## 1. 연구 질문과 주장 범위

> 고정된 표면 이웃 관계에서 국소 수송과 국소 반응을 처리할 때, 공통 State 표현과 State-Driven Geometry Coupling은 복합 현상의 전용 결합 구현을 줄이면서 미사용 표면·State 조합에 재사용될 수 있는가?

목표는 제어 가능한 현상학적 표면 상태 모델이다. State를 물리적 부피로 재정의하지 않는다. 정밀한 열역학, 압력 기반 유체, 임의의 강직 반응, 다층 재료 역학, 모든 Mesh에 대한 무조건적 지원은 주장하지 않는다. 현재 모델의 유효 범위 안에서 평가하고 제외되는 현상도 기록한다.

| 가설 | 필요한 증거 | 이 증거만으로 주장할 수 없는 것 |
|---|---|---|
| H1 기전 | Reaction에 따른 형상 변화가 후속 State 수송·반응에 재현 가능한 영향을 줌 | 신규성, 제작 생산성 |
| H2 재사용 | 고정 규칙을 미사용 Mesh·State 조합에 적용하고 실패와 조정 부담을 기록 | 임의 현상의 범용성 |
| H3 구조적 이점 | 공정한 모듈식 결합 대비 같은 품질에서 전용 결합·예외·재조정 또는 비용의 이점 | 기존 범용 연구보다 새롭다는 결론 |
| H4 연구 기여 | 확인된 구조적 이점이 가까운 선행연구의 구체적인 제약을 해결함 | SIGGRAPH 채택 보장 |

H1/H2 성공으로 H3/H4를 대신하지 않는다. 공통 Solver, GPU, 여러 State, Normal Map 적분, Cavity Filling, Sparse 자체를 신규성으로 전제하지 않는다.

## 3. 개발 사례와 초기화 계약

개발 사례는 기존 MarbleCube 기반 경사진 얇은 판과 Ice–Waterfilm–Heat다. 비균일한 Ice 띠, 정해진 Heat 입력 영역, 상류 Waterfilm 입력, 하류 관측 영역을 사용한다. 기존 Contact의 지원 형상으로 구성한다. 결과를 미리 ‘얼음댐 붕괴’ 또는 ‘물길 개방’으로 규정하지 않는다.

현재 Ice Profile의 모든 `cavityFillFactor`는 0이다. 첫 기전 실험은 이 조건을 유지해 Chart 최대 높이와 Cavity 모델 변경을 섞지 않는다. Profile 값은 개발 출발점이며 실제 동작을 검증한 실험용 값은 아니다.

초기화의 논리적 순서는 다음과 같다. 이를 구현할 테스트 도구는 후속 작업이다.

1. 모든 실행에서 같은 표면 graph, Profile과 채널 매핑을 준비한다.
2. 초기 Ice를 State에 반영하여 `S0`를 구성한다. 준비 중 평가용 Heat·Waterfilm 입력과 Reaction은 진행하지 않는다. 준비 과정에서 Transport가 있었다면 최종 `S0`와 준비 조건을 보존한다.
3. `S0`의 높이·위치·Normal·Concavity·가중치를 일관되게 계산해 `G0`를 만든다.
4. `S0`, `G0`, 입력 큐의 비어 있음과 동일성을 검사하고 평가 시간 `t=0`으로 정의한다. 초기 입력을 첫 평가 Step에 중복 적용하지 않는다.
5. 각 조건은 동일 `S0`에서 시작한다. D/E는 동일 `G0`에서 시작하며, A/B의 Solver는 macro+meso 형상을 사용한다.
6. 고정한 평가용 Heat·Waterfilm 입력 일정을 실행한다. 비교군마다 입력이나 초기 State를 별도로 보정하지 않는다.

현재 Profile에서 clamp·수송을 제외한 국소적 Ice→Waterfilm 전환은 높이 감소 방향이다. 실제로는 형상 기여 clamp, 이웃 수송, 여러 State 분포가 함께 작용한다. 높이 감소·유지·증가 모두 측정 결과로 받아들인다.

## 4. A–F 조건과 E의 정확한 의미

| 조건 | Reaction | Solver의 형상 | 목적 |
|---|---|---|---|
| A | OFF | macro+meso, State 축적 미반영 | 기본 수송 |
| B | ON | A와 동일 | 직접 반응 |
| C | OFF | 초기 축적과 이후 State 변화를 반영 | Reaction 없는 형상 결합 |
| D | ON | 초기 축적과 이후 State 변화를 반영 | 전체 결합 |
| E | ON | 초기 Ice 축적 직후 `G0` 고정 | 지속적인 형상 갱신의 효과 분리 |
| F | ON | D에서 Ice의 축적 기여만 0 | Ice 형상 기여의 역할 진단 |

Reaction OFF는 규칙의 `enabled:false`로 정의하고 State, 입력, 반응 이외의 파라미터는 유지한다. F는 첫 사례에서 Ice의 `accumulationFactor`만 0으로 둔다. 첫 사례는 Cavity 항이 0이므로 변경이 다른 직접 항에 영향을 주지 않는지 코드로 확인한 뒤 사용한다. 다른 Profile에 F를 적용할 때는 별도 확인이 필요하다.

E에서 고정하는 것은 Solver 형상의 전체 읽기 계약이다.

- source/target 위치, Normal, Concavity, 형상 의존 Transfer Weight와 그 파생 값을 `G0`에서 읽는다.
- `Transport.glsl`의 `effectiveLocalPosition()` 등 계산 중 재구성하는 위치도 `G0`를 사용한다. buffer만 고정하고 최신 accumulation을 섞지 않는다.
- 실제 State, Saturation, 입력, Reaction 조건은 계속 갱신한다. State 의존 수송 항까지 고정하지 않는다.
- 물체 transform, 중력, 정적 Meso와 Profile은 전체 평가 구간에 고정한다.
- 최신 State로 계산한 표시용 형상과 Solver용 `G0`를 구분한다. 표시용 갱신이 Solver buffer를 덮어쓰면 실험 무효다.
- E의 Solver 형상 및 형상 의존 가중치 불변성과 D/E의 초기 동일성을 자동 검사한다.

### 해석 경계

- D−B: State 형상 결합의 전체 효과. 초기 형상 효과도 포함한다.
- D−E: 초기 형상을 공유한 상태에서 지속적인 갱신을 허용한 효과.
- D−C: Coupling ON에서 Reaction을 추가한 효과. Geometry 매개 효과만 분리한 값은 아니다.
- D−F: Ice의 형상 기여를 제거한 개입 효과. 이후 State 궤적도 달라질 수 있다.
- 사전 선택 지표 Y에 대한 `I = Y_D − Y_B − Y_C + Y_A`는 비가산적 상호작용 진단이다. 비영점만으로 신규성이나 특정 경로의 인과성을 주장하지 않는다.

Heat의 수송도 공유 가중치 변화에 영향을 받을 수 있다. 따라서 A–F와 시간 순서만으로 ‘Waterfilm 경로 변화만이 냉각 변화를 매개했다’고 단정하지 않는다. 우선 H1은 전체 간접 결합의 존재로 제한한다. 특정 매개 경로를 주장하려면 채널별 Geometry 참조를 분리하는 추가 개입을 별도 명세해야 한다.

## 5. Baseline 사전 설계

| 대상 | 모델 소유권·확장 위치 | 평가 역할 |
|---|---|---|
| 독립 현상 구성 | 현상별 상태·수송·갱신; 상호작용은 별도 연결 필요 | 참고 조건. 결합 효과 품질을 동일하게 충족하지 않으면 우열 비교에서 제외 |
| 합리적 모듈식 결합 | 현상별 수송 모듈이 입력·출력·필요 필드를 선언; 공통 조정자·Reaction·Geometry 서비스가 연결 | 주 비교군 |
| MDSSP | 공통 State 표현과 Transport·Reaction 모델; Profile·규칙으로 지원 범위 내 확장 | 평가 대상 |

모듈식 비교군은 같은 시점의 모든 상태를 읽고, Transport 완료 후 공통 Reaction을 처리한 뒤 공유 형상을 구성한다. 모듈별 순차 실행으로 먼저 실행된 State만 새 값을 읽는 오차를 만들지 않는다. Reaction의 공급량 경쟁도 공통으로 처리한다.

### 허용 사항

- 동일 수송 식의 함수·템플릿 재사용, 데이터 기반 Reaction, 공통 배열·채널 ID·메모리 배치.
- Geometry 기여 등록과 공통 형상 합성, 재사용 가능한 어댑터와 의존성 선언.
- 캐시·배치·Kernel 통합·자원 공유. 모듈 수만큼 Dispatch하거나 코드를 복제하도록 강제하지 않는다.
- 동일 수준의 설정 인터페이스. UI 편의 차이를 계산 구조의 이점으로 계산하지 않는다.

첫 비교는 양쪽 표현 범위가 겹치는 동일 수송 식·반응·시간 순서를 사용해 아키텍처와 확장 작업을 평가한다. 서로 다른 현상별 수송 모델의 표현력 비교는 별도 연구 질문이다.

비교군이 일반적인 재사용만으로 MDSSP와 유사해지면 그 과정을 기록한다. 같은 결과·확장 부담·비용을 쉽게 얻는다면 H3은 지지되지 않는다. 반대로 특정 계산 계약이 필요했다면 그 계약, 도입 비용, 효과를 구체적으로 기록한다. 코드 파일을 합쳤는지 나눴는지만으로 새 아키텍처라고 주장하지 않는다.

Baseline 구조와 허용 최적화는 개발 사례 결과를 보기 전에 고정한다. 구현 중 명세 변경은 이유와 변경 전후를 남기고 양쪽에 대칭적으로 적용한다. 불리한 결과를 본 뒤 비교군에 제약을 추가하지 않는다.

## 6. 재사용 과제와 작업량 기록

| 사례 | 고정할 내용 | 허용 변경 | 상태 |
|---|---|---|---|
| 개발: MarbleCube + Ice/Waterfilm/Heat | 최종 선택 시 규칙·계수·입력·관측 영역 동결 | 개발 중 조정 이력 보존 | 미구성·미실행 |
| 미사용 1: Bunny + 동일 세 State | 기존 규칙과 재질 계수 | 표면에 맞춘 입력 위치·관측 영역 매핑 | 에셋 있음, 결합 결과 미검증 |
| 미사용 2: 원래 판 + Mud 추가 | 기존 세 State 및 Reaction | 미리 정한 Mud 파라미터·입력·초기 분포 | 실험 설정 미작성 |

Mud 설정은 기존 `Assets/SurfaceProfiles/DemoMud.SRProfile`을 출발점으로 하고, 채택할 값과 Cavity 사용 여부를 미사용 결과 관찰 전에 확정한다. 새 규칙을 조합했다는 실험과 임의의 새 물리 현상을 표현했다는 주장을 구분한다. Bunny와 Mud 결과가 유망하면 Mesh×State 조합의 교차 검증으로 확대한다.

미사용이라는 의미는 ‘프로젝트가 처음 보는 에셋’이 아니라 ‘이 연구 규칙·계수의 튜닝에 사용하지 않은 조건’이다. 알려진 데모에 대한 개발자의 사전 지식은 한계로 기록한다. 두 사례만으로 통계적 일반성을 주장하지 않는다.

작업마다 기반 구축 비용과 신규 현상 추가의 한계비용을 분리하고 다음을 diff·설정 이력으로 기록한다.

- 핵심 수송·반응·형상 코드 수정, 전용 결합 코드와 State 이름 특판, 어댑터·규칙 선언, 외관 전용 코드.
- 기존 규칙 변경 여부, 변경한 파라미터 종류와 조정 시도 수, 재초기화·실패·수정 사유.
- 입력 위치 매핑은 재질 재조정과 별도 기록. 속도·두께·반응 계수·임계값 변경은 재조정으로 기록.
- 무조정 결과를 먼저 보존하고, 실패 후 수정 허용 결과는 별도 단계로 표시.
- 양쪽에 같은 개발 정보와 수정 기회를 제공. 작성자의 MDSSP 숙련·순서 효과를 명시.

코드 줄 수는 보조 지표다. 생산성·학습 부담을 강하게 주장하려면 통제된 제작 과제 등 추가 증거가 필요하다. 현재 Ice의 외관은 전용 렌더링 경로를 포함하므로 ‘시뮬레이션 무수정’과 ‘완성된 외관 무수정’을 혼동하지 않는다.

## 7. 관측과 수치적 기준

Step n의 시작 State/Geometry, 적용 Input, limiter 이후 실제 directed edge flux, Decay, 반응별 누적 extent, Step 종료 State와 다음 Solver용 Geometry에 같은 Step ID를 부여한다. Raw 요청 Flux를 실제 수송량으로 대체하지 않는다. 내부 Reaction substep의 extent는 합산하며 마지막 substep scratch만 누적값으로 해석하지 않는다.

| 축 | 사전 선택 지표·기록 |
|---|---|
| 수송 | 하류 영역 Waterfilm 총량 시간열, 사전 지정 경계의 누적 순수송량; 보조로 분포 중심·도달 시간 |
| 반응 | 영역별 Ice 소비·Heat 잔량, 두 반응의 누적 extent, 입력과 Decay |
| 형상 | 실제 Solver 높이·Normal·가중치 변화, 표시용 형상과의 구분 |
| 수량 수지 | State별 Input/Transport/Decay/Reaction 수지, 비유한·음수, 공급량·시간 예산 진단 |
| 재사용 | 고정 규칙 유지 여부, 조정·특례·실패 이력 |
| 실행 비용 | Simulation GPU 중앙값·p95, 단계별 시간과 추가 할당 메모리; 전처리·렌더링 별도 |

`S`는 texel 총량이다. 총량 합산에 면적을 다시 곱하지 않는다. 서로 다른 해상도의 분포 비교에는 macro 표면의 공통 위치와 면적 측도를 사용한 `S/AreaScale` 평가 또는 영역 적분을 사용하고 보간 방법을 기록한다.

Ice Profile에서 `M = sum(ice + waterfilm)`은 융해·냉각 Reaction만으로 변하지 않는다. 외부 입력·제거·Decay·경계 수송이 있으면 그 실제 항을 반영한다. Heat와 모든 State의 단순 합이 보존되어야 한다고 가정하지 않는다. 이 검사는 현상학적 모델의 수량 수지이며 물리적 질량·에너지 보존의 증명이 아니다.

같은 graph의 구현 결과 비교에는 채널별 L1 차이와 절대 최대 차이를 함께 쓴다. 상대 오차 분모가 작은 경우를 위해 절대량을 병기한다. 정규화 상수는 결과를 보기 전에 고정한다. 도달 시간은 판정량 임계값·관측 시간창을 먼저 정하고, 미도달을 최대 시간으로 바꾸지 않는다.

### 기준 실행과 유효성 검사

- FP32 Raw Flux/Weights, Raw Flux cache ON을 기준 후보로 둔다. Adaptive·Sparse·채널 생략을 끄고 매 Step 전체 Geometry 갱신을 보장하는 기준 경로를 준비한다.
- `sparse_geometry=false`만으로 완전 갱신이라고 판단하지 않는다. 현재 Height dirty tolerance가 남아 있다. 강제 갱신 제어는 후속 도구 작업이다.
- 개발 출발 조건은 128 해상도, 14초, dt=1/60이다. dt=1/120, 1/240 및 256 해상도 비교로 결론의 안정성을 검사한다. 이는 수렴 증명이나 물리 기준해가 아니다.
- 시간 간격이 달라도 Contact를 같은 시뮬레이션 시간과 같은 총 입력으로 적용한다. 시작/종료 Step 경계 규칙과 초기화 시간을 고정한다.
- 관측 시점 후보는 t=0, 1, 2, 4, 8, 14초다. Step serial·simulated time·상태/형상의 버전을 함께 저장하고 drain 이후 상태로 대체하지 않는다.
- 예산 초과·산술 오류는 전체 구간에서 누적한다. 현재 최종 Reaction scratch 검사만으로 구간 전체가 정상이라고 주장하지 않는다.
- 오차·수량 수지·효과 크기의 허용 기준은 개발 사례의 수치 민감도를 확인한 뒤 미사용 결과를 보기 전에 동결한다. 시간·공간 오차를 엄밀한 상계나 독립 표본 통계로 해석하지 않는다.
- 동일 초기화 반복, A–F 실효 플래그, D/E 초기 동일성, E 형상 불변성, F의 변경 범위를 검사한다. 실패하면 해당 비교는 기여 가설 평가에 사용하지 않는다.

특정 물막 매개 경로의 주장, 열역학적 정확성, 화면의 아름다움은 위 지표만으로 평가하지 않는다.

## 8. 성능 비교와 자료 보존

진단 실행과 성능 실행을 분리한다. 동일 시뮬레이션 시점의 품질 동등성을 확인한 설정끼리 비교한다. 반복마다 초기 상태와 이벤트를 재설정하고 준비 과정이 평가할 현상을 소진하지 않도록 한다.

성능 실행의 준비 구간, 측정 구간, 반복 수, 실행 순서는 실행 전 성능 계획에서 고정한다. 시작 권고는 조건당 독립 실행 5회와 순서 교차/무작위화이며, 최종 숫자는 준비 비용과 반복 편차를 보고 결과 수집 전에 확정한다. 반복 프레임을 독립 실행 수로 세지 않는다. GPU·드라이버·빌드·실행 파일·SPIR-V·에셋 해시·실효 옵션·Step 수를 기록한다.

현재 Reaction은 기존 Pass 2 시간 구간에 포함된다. 별도 query를 추가하지 않았다면 Reaction 단독 시간을 보고하지 않는다. 메모리는 앱의 추적 할당량이며 실제 VRAM 상주량과 구분한다. 제품 기본 경로의 속도와 정확성 기준 경로의 비용도 분리한다.

실제 성능 실험을 시작할 때만 기존 ID를 확인해 PERF 번호를 부여하고 성능 문서에 실험 양식으로 기록한다. 이 문서에는 측정 수치·개선율을 만들지 않는다. 자료 구조는 `Performance-Data/README.md`의 study/experiment/plan/manifest/raw 규칙을 따른다. 실패·미지원·미실행은 서로 구분하고 재실행으로 덮어쓰지 않는다.

차이가 검출되지 않았다는 사실만으로 완전 동등성을 선언하지 않는다. 동등성 범위와 실용적 효과 기준을 사전에 정한다. 비용은 반드시 더 빨라야 하는 것이 아니라, 확인된 표현·확장 이점과 사전 지정한 Interactive 예산 안에서 함께 평가한다.

개발 사례를 바꾸는 경우 기존 실패와 교체 이유를 보존한다. 같은 가설이 실패할 때 성공 장면이 나올 때까지 바꾸는 방식은 금지한다. 개발 탐색 횟수·중단 예산은 실행 승인 단계에서 고정한다.

## 10. 선행연구와 주장 감사

[Günther et al. 2012, GPU-accelerated Interactive Material Aging](https://vc.tf.fau.de/publications/Guenther12VMV/Guenther12VMV.pdf)의 §4.1은 재료 관련 Normal을 입자 반응에 사용하며, §4.2는 재질별 계수의 장면 간 재사용, §4.3–4.5는 규칙·재료량·형상/외관 구성을 다룬다. ‘다중 재료·공통 규칙·재사용·형상 영향’ 자체를 MDSSP의 최초 기여로 쓰지 않는다.

확인된 구조 차이는 입자 매개 수송과 고정 표면 graph의 국소 Flux 수송이다. 이것만으로 우열이나 표현력 확대를 추론하지 않는다. 예를 들어 표면 밖/물체 간 이동과 표면 내 전파는 요구가 다르다. 모듈식 비교군을 Günther의 재현으로 표기하지 않는다.

H4 재판정에서는 다음 표를 증거와 함께 채운다. 현재는 미판정이다.

| 질문 | 현재 상태 |
|---|---|
| 본 사례의 상호작용을 기존 범용 Aging 규칙으로 구성할 수 있는가? | 구체적인 규칙 대응 분석 필요 |
| MDSSP만의 계산 계약은 무엇이며 일반적인 인터페이스와 어떻게 다른가? | 후보이지 확정 기여 아님 |
| 그 차이가 기존 방법의 어떤 제약을 해결하는가? | 실험·모델 분석 필요 |
| 그 이점 대신 잃는 표현 범위나 비용은 무엇인가? | 명시적 비교 필요 |

[SIGGRAPH 2026 심사 지침](https://s2026.siggraph.org/technical-papers-reviewer-instructions-ethics/)은 새 알고리즘이 없는 시스템 기여도 인정하지만 실질적 진전을 요구한다. 공개 구현이 없는 복잡한 선행 시스템 전체의 재구현을 첫 단계의 필수 조건으로 삼지 않는다. 논문에서 확인한 사실, 미기재, 추론을 구분한다.

## 11. 동결 단계와 다음 작업

이번 버전에서 고정한 것은 가설 분리, A–F의 의미, E의 읽기 계약, Baseline 허용 범위, 작업량 분류, 실패 해석과 결과 보존 규칙이다. 완전한 실행 사전등록으로 부르지 않는다.

| 시점 | 확정할 항목 | 현재 상태 |
|---|---|---|
| 구현·실행 착수 전 | 도구 변경 범위와 실행 승인, Baseline 설계 버전, 개발 탐색 중단 예산 | 미승인·미확정 |
| 개발 실행 전 | 판 transform, Ice/Heat/Waterfilm 입력 좌표·크기·시간·총량, 관측 영역·경계, 로그 schema | 미작성 |
| 미사용 사례 평가 전 | 최종 Profile·에셋·입력 해시, Mud 설정, 수치/실용 효과 허용 기준, 지표 정규화·도달 임계값, 비교 예산 | 개발 결과를 근거로 동결 예정 |
| 성능 결과 수집 전 | GPU/빌드/정밀도·품질 조건, 준비·측정 구간, 반복·순서, Interactive 목표 비용 | 미확정 |

허용 기준은 효과가 크게 보이도록 사후 선택하지 않는다. 개발에서 선택한 기준은 미사용 사례로 검증하고 모든 조정 이력을 보존한다. 미사용 결과를 본 후 변경하면 해당 사례는 개발 사례로 재분류하고 별도 평가 조건을 정한다.

진행 순서: 사전 명세 → 승인 후 계측/정확성 준비 → Ice 기전 검증 → 미사용 재사용 검증 → 사전 설계된 Baseline 구현·비교 → 선행연구 대비 재판정. 선행연구의 주장 범위 점검은 실험 전부터 수행한다.

## 12. 실행 착수 기록 — 2026-10-26

원래 명세를 위에 보존하고 실행 선택을 이 절에 추가한다. 결과와 실패는 성능 문서 PERF-041에 기록한다.

- 입력과 조건은 `Performance-Data/20261026-coupling-study/PERF-041-coupling/plan.json`에 첫 실행 전에 저장했다. 한 가지 개발 분포만 사용하고 계수 탐색은 하지 않는다.
- 실제 Mesh의 production OBJ/UV mapping과 GPU Solver를 사용하는 headless 실행기를 택했다. 앱 Benchmark의 drain·렌더링 시간과 분리하며 이 경로는 앱 전체 성능 비교가 아니다.
- Contact rasterization 대신 기준 면적당 해석적 입력장을 직접 올린다. 초기 Ice와 입력 사건의 총량·시점이 명시되며 이 차이를 결과의 한계로 보고한다.
- 초기 Ice: `3.5 exp(-(u/.30)^4-(v/.10)^4)`. Heat: 중심 `(-.08,.02)`, 폭 `(.16,.14)`의 Gaussian × .2. Waterfilm: 중심 `(0,.30)`, 폭 `(.18,.08)`의 Gaussian × .15. 두 사건 입력은 `t=0,.25,...,11.75초`. 총량으로 올릴 때 각 texel의 AreaScale을 곱한다.
- MarbleCube는 scale `(1.65,2.2,.22)`, X 회전 8도. Bunny는 기존 Scene의 scale `6.42264883`, X 회전 90도. Bunny만 월드 bounding box의 x·z 정규화 좌표로 입력장을 매핑한다.
- 첫 연구에서는 Normal Map 없는 macro 형상과 0 meso height를 사용한다. Mud의 기존 계수는 유지하되 Cavity·Cavity retention 세 계수만 사전 선언대로 0으로 둔다.
- 평가 구간 14초, 128에서 60/120/240 Hz, 256에서 60 Hz. D 반복과 dirty 갱신 대비를 추가한다. 미사용 Bunny·Mud는 128/60 Hz A–F로 탐색한다.
- 유효성 gate: 음수·비유한·반응 예산·산술 오류·E 형상 변경 0, Ice+Waterfilm 수지 오차를 초기량+총 입력으로 정규화해 `1e-5` 이하. 이는 FP32 수량 검사 기준이며 연구적 효과 크기의 합격선이 아니다.
- 계측 ON/OFF의 State 동일성은 짧은 D 실행으로 먼저 확인한다. 반응량은 실제 내부 substep extent를 누적하고 Raw Flux에 source alpha를 곱해 수송 수지를 검사한다.
- GPU timestamp는 진단 실행의 기술 통계로만 기록한다. 5회 독립 앱 성능 측정과 모듈식 Baseline 우위 검증은 수행했다고 간주하지 않는다.

### 실행 범위 변경과 결과 연결 — 2026-10-27

위 원래 계획은 보존한다. 본 실험 60 Hz D/E를 본 뒤, 시간·해상도 정밀화 및 미사용 결과를 보기 전에 진단 비용을 이유로 **주 비교 D/E의 정밀화 + 미사용 B/D/E**에 범위를 집중했다. 고정 입력/계수는 바꾸지 않았다. `execution-amendment.json`의 20조건을 완료했고 원래 전체 조건 실행으로 표기하지 않는다.

Dense/Sparse D/E의 최종·중간 State/Geometry/Flux 동등성을 먼저 확인한 뒤 후속 실행은 기존 Sparse Solver를 사용했다. 외부 입력 시 전체 활성 집합을 seed하고 Geometry는 매 Step 전체 갱신했다. E는 모든 Solver 형상 참조를 G0로 고정했다. 별도의 D-dirty 대조는 기존 높이 기준에 의한 **전체** Geometry 갱신 여부를 비교하며, 2-hop Sparse Geometry의 검증과 구분한다.

[[05_Experiments/02_Performance-Measurements|PERF-041 결과]]: H1은 판에서 지지, H2는 제한된 지지(특히 Bunny seam 링크 누락과 작은 Mud 추가 효과), H3/H4는 미검증. 31회·25,740 Step, 초기 실패 1회·의도적 중단 1회 보존. 모듈식 Baseline·앱 성능·Normal Map Meso·렌더링 품질 평가를 수행한 것으로 간주하지 않는다.

## 13. 후속 Baseline 구체화 — 2026-10-27

[[05_Modular-Baseline-Spec|모듈식 Baseline 명세 v1]]과 `Scripts/Research/Plans/modular-baseline-v1.json`에서 §5–8의 후속 비교를 구체화했다. 공통 서비스·수송 helper·generic module factory·batching/fusion을 허용한다. 초기 모듈 구현의 불필요한 dispatch/복사나 작성자의 숙련도 차이를 모델 우위로 해석하지 않는다.

T0–T3의 동일 결과 gate, 확장 부담의 분류·출발점, 주 비용 조건·반복 순서, H3 기각 규칙을 고정했다. 기존 결과를 본 뒤 작성한 명세이며 T0/T1을 새로운 미사용 평가로 부르지 않는다. 이번 작업은 명세 작성이고 Baseline 구현·실험 결과는 아직 없다.

## 14. 후속 비교·선행모델 분석 결과 — 2026-10-27

§13은 명세 동결 당시의 기록으로 보존한다. 이후 실제 Baseline 구현·실행은 [[05_Experiments/02_Performance-Measurements|PERF-042]]에 기록했다. 26회·평가 13,260 Step, 감사 오류·쌍별 gate 실패 0. 본 진단의 7 U/M 쌍이 일치했고 양쪽 모두 선언 확장으로 과제를 처리했다. 사전 명세의 구조적 중단 규칙에 따라 256 진단 4회·정식 비용 40회는 미실행이다. v1 과제에서 조정 구조에 의한 확장 부담 우위는 지지되지 않았다.

[[06_Prior-Model-Differentiation|H4 원문·코드 대조]]에서 §10의 질문을 다음과 같이 판정했다. 이번 후속 작업은 문헌·모델 분석이며 새 성능 실험이 아니다.

| §10의 질문 | 현재 판정 |
|---|---|
| 본 사례의 상호작용을 기존 범용 Aging 규칙으로 구성할 수 있는가? | 주요 인과관계는 대응되는 선례 또는 일반 rule로의 대응 추론이 있다. 같은 수치해의 재현은 미실행이며 기존 방법으로 불가능한 사례로 사용할 근거가 없다. |
| MDSSP의 구체적 계산 계약은 무엇인가? | 고정 표면 graph의 공급량 제한 scalar flux, 선언 반응·Input/Incoming 장부, State 기반 공유 형상 갱신. 계약의 존재와 신규성은 별개다. |
| 그 차이가 기존 방법의 어떤 제약을 해결하는가? | 현재 중요한 제약 해결·비용/제작 우위가 입증되지 않았다. |
| 대신 잃는 표현 범위는 무엇인가? | 입자식 공중/물체 간 이동, 층 순서·서로 다른 층의 metric/속도·응력, 큰 변형의 graph 재구성, 물리적 부피/열량 해석을 일반적으로 제공하지 않는다. |

현재 구현·증거의 종합 분류는 **기존 연구의 시스템 통합에 가까움**이다. H1의 실제 coupling 효과는 유지하되 H3/H4의 새 시스템 기여로 확대하지 않는다. 지정 7편의 원문 분석이 전체 선행연구의 비신규성 증명은 아니다. 향후 제작 가치 또는 실제 수치적 실패를 검증할 때의 재개 조건과 미확인 항목은 H4 문서를 따른다.

## 15. Meso 후속 검증 — 2026-10-27

사용자 후속 승인 후 [[05_Experiments/02_Performance-Measurements|PERF-043]]에서 알려진 높이의 normal 및 실제 벽돌 Normal Map을 비교했다. 원래 32조건과 대조/재현을 포함한 35회·GPU 5,580 Step에서 표준 동일 제약 LS가 합성 높이 복원 오차를 줄였으나 후속 물막의 차이는 작았다. 제한된 조건에서 새 Meso 알고리즘의 필요성을 확인하지 못했으며, 기여 판정은 바꾸지 않는다. 기존 제품의 Solver/복원 식을 개선하거나 참조 알고리즘을 채택한 실험도 아니다. render-mesh unit test 실패 1개와 shader 사전 보관 누락·대표 재현의 제한은 PERF-043에 보존했다.

# C++ 주석 작성 규칙

이 문서는 C++ 코드의 파일 설명과 함수 설명을 일관되게 작성하는 규칙을 정한다. 파일·함수 설명에는 Doxygen block comment인 `/** ... */`를 사용한다.

## 기본 원칙

| 원칙 | 기준 |
|---|---|
| 형식 통일 | 파일과 함수 설명은 `/** ... */` 형식으로 작성한다. |
| 목적 중심 | 코드의 동작을 그대로 반복하지 말고, 책임·계약·주의할 점을 설명한다. |
| 간결성 | 필요한 정보만 남기고, 구현을 줄마다 해설하지 않는다. |
| 최신성 | 코드의 동작이나 계약이 바뀌면 주석도 함께 수정한다. |
| 선택적 작성 | 이름과 선언만으로 충분히 명확한 단순 함수에는 주석을 생략한다. |

## 파일 상단 주석

모든 C++ 헤더와 구현 파일의 맨 위에 `@file`과 `@brief`를 포함한다. include보다 앞에 둔다. 다른 파일과 맞춰야 하는 불변조건이나 중요한 설계 제약이 있을 때만 `@note`를 추가한다.

```cpp
/**
 * @file SurfaceStateTypes.h
 * @brief Surface State 채널과 Profile 데이터의 CPU 표현을 정의한다.
 * @note State 이름과 Registry ChannelIndex의 대응은 CPU/GPU 데이터에서 동일해야 한다.
 */
```

파일 주석에는 파일 목적과 범위를 적는다. 파일에 선언된 모든 type과 함수를 목록처럼 나열하지 않는다.

## 함수 주석

함수의 역할을 `@brief`로 설명한다. 필요한 경우 입력 조건에 `@param`, 반환값의 의미에 `@return`, 호출자가 처리해야 하는 예외에 `@throws`를 사용한다.

```cpp
/**
 * @brief Surface Response Profile의 파라미터와 전이를 검증한다.
 * @param Data 검증할 Profile 데이터.
 * @throws std::invalid_argument 값이 유한하지 않거나 허용 범위를 벗어난 경우.
 */
void ValidateSurfaceResponseProfileData(const SurfaceResponseProfileData& Data);
```

함수 주석은 다음 경우에 특히 작성한다.

- 함수 이름만으로 드러나지 않는 전제 조건이나 부수 효과가 있다.
- 반환값의 단위·소유권·유효 기간을 설명해야 한다.
- 특정 입력에 예외를 던지거나 실패를 반환한다.
- 데이터 순서, 범위, 호출 순서 같은 외부 계약을 지킨다.

단순 getter처럼 이름과 반환 타입이 의도를 충분히 나타내는 함수는 주석을 반복해서 붙이지 않는다. 선언과 정의에 같은 설명을 중복 작성하지 말고, public API는 헤더 선언에 설명을 둔다. 파일 내부 helper는 필요한 경우 구현 파일의 함수 정의 위에 설명을 둔다.

## 인라인 주석

함수 내부의 짧은 설명이나 특정 코드 옆의 설명에는 일반 `//` 주석을 사용할 수 있다. 알고리즘의 이유, 예상하기 어려운 제약 또는 의도적인 예외를 설명하고, 코드에서 바로 읽히는 사실을 반복하지 않는다.

```cpp
// 같은 texel을 여러 Contact가 갱신할 수 있으므로 입력량을 누적한다.
AccumulateInputDelta(TexelIndex, InputAmount);
```

## 금지할 패턴

- 주석과 코드가 서로 다른 동작을 설명하는 상태로 방치하지 않는다.
- 함수 본문을 한 줄씩 번역하거나 변수 이름을 문장으로 반복하지 않는다.
- 근거가 불분명한 `TODO`, `FIXME`를 남기지 않는다. 필요한 작업 항목은 [[TODO|TODO]] 또는 해당 계획 문서에 기록한다.
- 모든 사소한 함수에 기계적으로 주석을 붙이지 않는다.

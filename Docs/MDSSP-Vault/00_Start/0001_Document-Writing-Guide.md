# 문서 작성 가이드

이 문서는 MDSSP Vault 문서를 일관되고 빠르게 읽을 수 있도록 구성하는 기준을 정한다. 내용의 정확성과 문서별 책임은 [[01_Project-Policy/0000_Documentation|문서 정책]]을 우선한다.

## 기본 원칙

| 원칙 | 작성 방법 |
|---|---|
| 결론 우선 | 절의 첫 문장에서 결정, 결과 또는 핵심 상태를 먼저 밝힌다. |
| 한 문서 한 책임 | 정책, Architecture, ADR, 구현 계획과 실험 결과를 한 문서에 혼합하지 않는다. |
| 확정도 구분 | 확정 사항, 구현 기본안, 검토 필요 항목을 명시적으로 구분한다. |
| 반복 최소화 | 기준 문서를 링크하고 같은 정의나 수식을 여러 문서에 복제하지 않는다. |
| 검증 가능성 | 구현 또는 실험 문서에는 입력 조건과 기대 결과를 함께 기록한다. |
| 용어 일관성 | [[01_Project-Policy/0001_Glossary|Glossary]]의 공식 표기와 대소문자를 따른다. |

## 표 사용 기준

여러 항목이 같은 기준으로 반복되거나 서로 비교되는 내용은 표를 우선한다.

| 내용 | 권장 열 구성 | 예시 |
|---|---|---|
| 파라미터 정의 | 이름 / 의미 / 범위 / 기본값 | SRProfile 파라미터 |
| 자료구조 | 필드 / 자료형 / 단위 / 역할 | GPU buffer layout |
| 책임 분리 | 구성요소 / 책임 / 소유 데이터 | Engine module 구분 |
| 선택지 비교 | 대안 / 장점 / 단점 | ADR Alternatives |
| 테스트 계획 | 검증 대상 / 입력·조건 / 기대 결과 / 방식 | Parser validation |
| 일정 | 시점 / 목표 / 산출물 | 주차별 계획 |
| 상태 점검 | 항목 / 상태 / 남은 작업 | Branch 완료 조건 |

표를 작성할 때는 다음을 지킨다.

- 열 제목만 읽어도 비교 기준을 알 수 있게 쓴다.
- 한 행에는 하나의 개념이나 검증 사례만 둔다.
- 수치에는 범위와 단위를 함께 적는다.
- 코드 식별자, 파일 확장자와 값은 backtick으로 표시한다.
- 셀 안에 긴 문단이나 여러 단계의 절차를 넣지 않는다.
- Markdown 표 안의 Obsidian link alias 구분자 `|`는 `\|`로 작성한다.

## 표 대신 다른 형식을 쓰는 경우

| 내용 | 권장 형식 | 이유 |
|---|---|---|
| 처리 순서 | 번호 목록 또는 flowchart | 선후 관계를 명확하게 보여준다. |
| 설계 이유와 맥락 | 짧은 문단 | 인과관계를 자연스럽게 설명할 수 있다. |
| 디렉터리·소유권 계층 | Tree 형태의 code block | 포함 관계를 한눈에 볼 수 있다. |
| 수식 | LaTeX block과 기호 표 | 계산식과 기호 정의를 분리할 수 있다. |
| 실제 API·자료형 | 짧은 code block | 구현 계약을 정확하게 보존한다. |
| 단순 항목 두세 개 | 짧은 bullet list | 표보다 빠르게 읽힌다. |

## 테스트 문서 형식

테스트 문서에는 대상, 입력 조건, 기대 결과와 테스트 방식을 기록한다. 공통 원칙은 [[06_Testing/0000_Testing-Guide|Testing Guide]]에, 구체적인 사례는 주제별 테스트 문서에 둔다. 새 테스트 문서는 [[00_Start/Templates/0005_Test-Plan|Test Plan 템플릿]]을 사용한다.

## 문서 구조

긴 문서는 다음 순서를 기본으로 하되, 문서 책임에 맞지 않는 절은 생략한다.

1. 제목과 상태
2. 목적과 범위
3. 핵심 결정 또는 요약 표
4. 자료구조나 처리 순서
5. 테스트와 완료 조건
6. 미결 사항 또는 제외 범위
7. 관련 문서

## 작성 후 확인

| 확인 항목 | 기준 |
|---|---|
| 경로 | 파일 이동 후 내부 link가 실제 파일을 가리킨다. |
| 중복 | 동일 정의의 기준 문서가 하나다. |
| 표기 | 공식 용어, 확장자와 대소문자가 일치한다. |
| 상태 | 계획과 구현 완료를 구분한다. |
| 표 | 반복 관계는 표로 정리되고 긴 설명은 표 밖에 있다. |
| 코드 | 예시와 현재 자료형·채널 순서가 모순되지 않는다. |
